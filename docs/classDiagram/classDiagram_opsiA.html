1. Frontend Class Diagram (Guest & Customer Portal — BCE)

Deskripsi: Halaman UI (Boundary) untuk Guest dan Customer. Menampilkan hubungan pewarisan antara Guest dan Customer terhadap base class User, serta relasi pemanggilan logika controller untuk Registrasi, Login, Katalog, Simulasi, Booking Cash/Kredit, dan Pembayaran. 
classDiagram
    direction LR
    %% Boundary (UI Pages)
    class HalamanUtama {
        +tampilkanHeader() : void
        +tampilkanFooter() : void
    }
    <<boundary>> HalamanUtama

    class HalamanRegistrasi {
        +tampilkanFormRegistrasi() : void
        +submitRegistrasi() : void
    }
    <<boundary>> HalamanRegistrasi

    class HalamanLogin {
        +tampilkanFormLogin() : void
        +submitLogin() : void
    }
    <<boundary>> HalamanLogin

    class HalamanKatalog {
        +tampilkanKatalog() : void
        +pilihKategori() : void
        +tampilkanDetailMotor() : void
        +hitungSimulasi() : void
    }
    <<boundary>> HalamanKatalog

    class HalamanBookingCash {
        +tampilkanFormBookingCash() : void
        +submitBookingCash() : void
    }
    <<boundary>> HalamanBookingCash

    class HalamanBookingKredit {
        +tampilkanFormBookingKredit() : void
        +submitBookingKredit() : void
    }
    <<boundary>> HalamanBookingKredit

    class HalamanPembayaran {
        +tampilkanInvoice() : void
        +pilihMetodeBayar() : void
    }
    <<boundary>> HalamanPembayaran

    %% Control
    class AuthControllerClient {
        +register(data) : Promise
        +login(credentials) : Promise
    }
    <<control>> AuthControllerClient

    class KatalogControllerClient {
        +getKatalog() : list
        +hitungCicilan(dp, tenor) : list
    }
    <<control>> KatalogControllerClient

    class BookingControllerClient {
        +buatJadwal() : void
    }
    <<control>> BookingControllerClient

    class PembayaranControllerClient {
        +prosesBayar() : void
    }
    <<control>> PembayaranControllerClient

    %% Entity (Data Models)
    class User {
        -id : BigInt
        -email : Varchar
        -name : Varchar
    }
    <<entity>> User

    class Guest {
        -sessionId : Varchar
    }
    <<entity>> Guest

    class Customer {
        -phone : Varchar
        -address : Text
    }
    <<entity>> Customer

    class Motors {
        -id : BigInt
        -name : Varchar
        -brand : Varchar
        -price : Decimal
    }
    <<entity>> Motors

    class KategoriMotor {
        -id : BigInt
        -nama : Varchar
    }
    <<entity>> KategoriMotor

    class JadwalServis {
        -id : BigInt
        -service_date : Date
    }
    <<entity>> JadwalServis

    class PembayaranServis {
        -id : BigInt
        -total_cost : Decimal
    }
    <<entity>> PembayaranServis

    %% Generalization (Inheritance)
    Guest --|> User
    Customer --|> User
    HalamanRegistrasi --|> HalamanUtama
    HalamanLogin --|> HalamanUtama
    HalamanKatalog --|> HalamanUtama
    HalamanBookingCash --|> HalamanUtama
    HalamanBookingKredit --|> HalamanUtama
    HalamanPembayaran --|> HalamanUtama

    %% Dependency (Boundary ..> Control)
    HalamanRegistrasi ..> AuthControllerClient : menggunakan
    HalamanLogin ..> AuthControllerClient : menggunakan
    HalamanKatalog ..> KatalogControllerClient : menggunakan
    HalamanBookingCash ..> BookingControllerClient : menggunakan
    HalamanBookingKredit ..> BookingControllerClient : menggunakan
    HalamanPembayaran ..> PembayaranControllerClient : menggunakan

    %% Association (Control --> Entity)
    AuthControllerClient --> User : registrasi/validasi
    KatalogControllerClient --> Motors : query
    BookingControllerClient --> JadwalServis : set
    PembayaranControllerClient --> PembayaranServis : update

    %% Structural Relationships (Entity to Entity)
    KategoriMotor "1" o-- "*" Motors : "mengelompokkan (Aggregation)"
    Customer "1" *-- "*" JadwalServis : "melakukan (Composition)"
    JadwalServis "1" *-- "1" PembayaranServis : "mencakup (Composition)"
Relasi Sistem Notasi UML & Jenis Keterangan Bisnis & Sistem
Halaman UI → HalamanUtama Halaman --|> HalamanUtama
Generalization (Inheritance)		 Halaman login, registrasi, katalog, dll. mewarisi layout dasar, header, dan footer dari parent boundary HalamanUtama. Halaman utama ini sendiri tidak berdiri mandiri.
Guest / Customer → User Guest/Customer --|> User
Generalization (Inheritance)		 Atribut dasar user seperti nama dan email diwariskan langsung ke kelas Guest (yang memiliki session) dan Customer.
Halaman UI → Controller Boundary ..> Control
Dependency (Ketergantungan)		 Halaman frontend bergantung searah kepada Controller terkait untuk memproses logika data.
Controller → Model Entity Control --> Entity
Association (Asosiasi)		 Controller bertindak sebagai pengolah logika yang memproses data database.

2. Backend Class Diagram — Opsi A (Arsitektur Terpusat)

Deskripsi: Halaman UI Dashboard (Boundary) untuk Admin dan Montir dengan controller bisnis. **Opsi A menggunakan satu AuthController terpusat di Backend (tidak diduplikasi di diagram backend)** dan memanfaatkan pewarisan Admin/Montir --|> User untuk autentikasi. Halaman Dashboard diproteksi langsung di level routing (middleware). 
classDiagram
    direction LR
    %% Boundary (UI Dashboards)
    class HalamanLoginBackend {
        +tampilkanFormLogin() : void
        +submitLogin() : void
    }
    <<boundary>> HalamanLoginBackend

    class HalamanDashboard {
        +tampilkanSidebar() : void
        +tampilkanHeader() : void
    }
    <<boundary>> HalamanDashboard

    class DashboardAdmin {
        +tampilkanLaporan() : void
        +verifikasiBooking() : void
    }
    <<boundary>> DashboardAdmin

    class DashboardMontir {
        +tampilkanDaftarKerja() : void
        +updateStatusServis() : void
    }
    <<boundary>> DashboardMontir

    %% Control
    class AuthControllerBackend {
        +login(credentials) : Promise
        +logout() : void
    }
    <<control>> AuthControllerBackend

    class BookingController {
        +buatJadwal() : void
    }
    <<control>> BookingController

    class PembayaranController {
        +prosesBayar() : void
    }
    <<control>> PembayaranController

    class MontirController {
        +catatPengerjaan() : void
        +selesaikan() : void
    }
    <<control>> MontirController

    class LaporanController {
        +generateLaporanServis() : JSON
        +generateLaporanKeuangan() : JSON
    }
    <<control>> LaporanController

    %% Entity
    class User {
        -id : BigInt
        -email : Varchar
        -name : Varchar
    }
    <<entity>> User

    class Admin {
        -level : Varchar
    }
    <<entity>> Admin

    class Montir {
        -keahlian : Varchar
    }
    <<entity>> Montir

    class JadwalServis {
        -id : BigInt
        -status : Varchar
    }
    <<entity>> JadwalServis

    class Servis {
        -id : BigInt
        -service_notes : Text
    }
    <<entity>> Servis

    class PembayaranServis {
        -id : BigInt
        -payment_status : Varchar
    }
    <<entity>> PembayaranServis

    %% Generalization (Inheritance)
    Admin --|> User
    Montir --|> User
    DashboardAdmin --|> HalamanDashboard
    DashboardMontir --|> HalamanDashboard

    %% Dependency (Boundary ..> Control)
    HalamanLoginBackend ..> AuthControllerBackend : menggunakan
    HalamanDashboard ..> AuthControllerBackend : divalidasi (via middleware)
    DashboardAdmin ..> BookingController : mengelola
    DashboardAdmin ..> PembayaranController : memantau
    DashboardAdmin ..> LaporanController : request laporan
    DashboardMontir ..> MontirController : menggunakan

    %% Association (Control --> Entity)
    AuthControllerBackend --> User : validasi/autentikasi
    BookingController --> JadwalServis : update
    PembayaranController --> PembayaranServis : query
    LaporanController --> PembayaranServis : rekap
    MontirController --> Servis : update
    MontirController --> JadwalServis : update

    %% Structural Relationships (Entity to Entity)
    JadwalServis "1" *-- "1" Servis : "merekam (Composition)"
    Servis "1" *-- "1" PembayaranServis : "mencatat (Composition)"
Relasi Sistem Notasi UML & Jenis Keterangan Bisnis & Sistem
Dashboard UI → HalamanDashboard Dashboard --|> HalamanDashboard
Generalization (Inheritance)		 Dashboard Admin dan Montir mewarisi sidebar, header, dan layout dasar dari parent HalamanDashboard. Halaman dashboard ini tidak dapat diakses langsung tanpa peran spesifik.
Admin / Montir → User Admin/Montir --|> User
Generalization (Inheritance)		 Admin dan Montir mendapatkan pewarisan langsung seluruh kredensial dari kelas induk User di database back-office.
HalamanLoginBackend → AuthControllerBackend Boundary ..> Control
Dependency (Ketergantungan)		 Halaman login backend bergantung pada AuthControllerBackend untuk memproses validasi data masuk admin/montir.
Dashboard UI → Controller Boundary ..> Control
Dependency (Ketergantungan)		 Dashboard back-office terhubung dengan controller untuk memanggil logika bisnis masing-masing.
JadwalServis → Servis JadwalServis "1" *-- "1" Servis
Composition (Komposisi)		 Record pengerjaan Servis fisik terikat mati dengan booking JadwalServis.
